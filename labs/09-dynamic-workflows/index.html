2.Customer brief

Hello — I am the external security auditor Harbourline has hired ahead of its payment-provider renewal. Harbourline runs two brands, Lumen Home (USD) and Trailhead Supply (EUR), on one Node API and one PostgreSQL database. Every request names its brand in the X-Harbourline-Brand header. Last quarter a Lumen merchandiser opened a Trailhead order by pasting its link. Harbourline says that was a one-off. I need proof, not reassurance.

What I need from you:

  1. Proof that no endpoint leaks across brands. That means every route the API serves, not a sample. For each endpoint I want a verdict: can a caller from one brand read or change a row that belongs to the other brand? Back each verdict with a file and line I can check.
  2. Confirmed leaks fixed, and each fix verified by someone other than whoever wrote it. I will not accept "the fixer's tests pass" as verification.
  3. A cost I can put in my report. Harbourline wants to use Devin's dynamic workflows to do this in parallel. Finance wants a number per agent, not a monthly total.

You have seven calendar days before my report goes to the payment provider. Today you have one three-hour working block. Finance has said the first run must be small: try the method on a slice before paying for the whole API.

3.Stakeholders and constraints

  • The auditor (me) signs off on evidence. I read diffs, test names, run logs and cost tables. I do not read prompts.
  • Harbourline's platform lead owns main and has a freeze on it. No fix lands on main this week. Every remediation goes on a throwaway branch and is closed without merging. The known defects stay in the baseline because other teams train on them.
  • Harbourline's finance lead approves ACU spend. They want to see the slice cost before they approve the full run.
  • Brand merchandisers (one per brand) can confirm what they should and should not be able to see.
  • Forbidden: changes on main, changes to packages/contracts/, real credentials, and any production database.
  • Output: a short audit note covering endpoint count, verdicts, the fix branch, the verifier's verdict, and per-agent ACU. Bring the workflow's execution graph and run log. Keep the note out of commits.

What “clean” looks like

On main with git status --short empty, no local audit/* branches, and the seed-spec dataset loaded for both brands. The planted cross-brand-leak (GET /orders/:orderId ignores the caller's brand) is still present and its test in services/api/test/planted.test.ts is still skipped.

5.Acceptance criteria

You are done when someone who was not in the room can see each of the following.

  1. Full endpoint inventory. The audit note lists every endpoint served by services/api (22 on the clean baseline) with one verdict each, leaks or isolated, and a file:line reference for every verdict. The inventory was derived from the code, not typed from memory.
  2. Slice first. The run log shows a first run limited to a small slice of route files, and the slice's cost appears before any wider run. Widening the run changes data, not the workflow's structure.
  3. The workflow script exists only in your hidden notes. It uses separate agent calls for audit, fix and verify, chains them so results flow from one stage to the next, and returns small flat structured outputs. Nothing about it is committed to main.
  4. Execution graph captured. A screenshot of the workflow run shows its phases and its agents.
  5. At least one agent failure handled. The run log shows an agent that failed or returned invalid output, and shows what the script did about it (bounded retry, corrective re-ask or loud stop). The audit note says whether that failure changed any verdict.
  6. Resume demonstrated. A second invocation with the same run ID shows completed agents replaying from the record rather than starting new sessions, and you can explain what would make an agent run again.
  7. Fixes on throwaway branches only. Each confirmed leak has a fix branch named by the script, so no two fixers can collide, with a test that fails on the baseline and passes on the branch. main still contains every planted defect, and the branch is closed or deleted without merging.
  8. Independent verification. A different agent from the fixer gives a pass/fail verdict per fix branch, based on its own check.
  9. ACU per agent reported. The audit note has a table with one row per agent (including retries) plus the run total. It also projects the cost of the full fan-out from the slice numbers.
  10. Injectors absorbed. The note says how branch names avoid collision, and predicts what adding a date to a prompt would do on resume.
  11. Articulation drill completed with the voice coach (section 8), or against a timer offline. The gap report (or self-score) is saved next to the audit note and not committed.

8.Articulation drill (voice coach)

The coach plays the external auditor from the brief. The auditor reads evidence, not prompts, and expects numbers.

60-second framing

Lead with what the auditor gets, then how, then what it costs. Stems you can use:

  • "You asked for proof about every endpoint; here is how many there are and how I covered them…"
  • "I split the work into stages because…"
  • "The first run was deliberately small: …"

Sinhala-first note: say the verdict first. Do not walk the auditor through the method before you give the answer.

Think-aloud checkpoint (T+20)

The coach asks what you are looking at and what you will check next. Answer with I see… I think… I'll try… I'll check…. At T+20 you should be talking about the inventory and the shape of the slice, not the fix.

Think-aloud checkpoint (T+120)

Same four verbs, later in the run. By now something has gone wrong or nearly gone wrong. Name it, and say how the run noticed it. If you need to read the log, say "Give me ten seconds to read the run log" rather than going silent.

Three-minute auditor update

Skeleton: Verdict → Coverage → Failure and recovery → Fix and verification → Cost → Ask. Use one number per sentence. Name the cost per agent, not just a total. Pause after each heading word.

Objection round

The auditor raises one technical and one commercial objection, in character, about 90 seconds each. Reply with: acknowledge → boundary → evidence → offer. The commercial objection cannot be answered without numbers from your own run. The objections themselves are not printed here.
