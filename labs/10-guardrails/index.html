2.Customer brief

Hi — I'm the CISO at Harbourline. Devin sessions now run for both brands, Lumen Home and Trailhead Supply, every day, and I have no written answer to the first question my auditors ask: where can those machines talk to, and who decides?

Here is what I will sign:

  1. Two destinations, nothing else. A session may install packages from the public package registry (registry.npmjs.org) and call the PayGate sandbox. Not production PayGate, not GitHub's API, not random websites, and no MCP servers until we approve one.
  2. Nobody switches it off. A developer, a team lead or a session choosing "no profile" must not get around it. Teams may be stricter than me; never looser.
  3. Robots are stricter than people. The webhook-triage automation reads code and reports; it does not push, and it does not create other sessions.
  4. No escape hatch through delegation. If a session spins up helper sessions, they live under the same rules.
  5. Screen what comes in. People and PR comments will try to talk Devin into leaking things or skipping review. I want to know when that happens, and to stop the obvious ones.
  6. Tell me when a change lands. If I tighten the rules at 3 p.m., I need to know which sessions are still on the old rules and for how long.

You have seventy-five minutes. Finish with a three-minute update I can repeat to the audit committee in plain language — I care about the difference between what we require and what we merely suggest.

3.Stakeholders and constraints

  • The CISO (the coach) signs off. She reads the policy matrix and the resolver output, not your prompts. She will ask what is enforced, by whom, and from when.
  • The platform lead wants pnpm install to keep working in every session and in snapshot builds, and will push back on anything that slows teams down.
  • The payments lead needs the PayGate sandbox reachable from sessions and from the webhook-triage automation's investigations only when it needs them.
  • The enterprise admin is the only person who can save an enterprise-wide profile or change guardrail settings. You may not be that person: if you are not an admin, you work offline and hand the admin a change request.
  • Forbidden: changes on main, editing packages/contracts/, binding a draft profile to the whole organization before it has been resolved offline, testing against production PayGate, and putting any token in a profile, a fixture or a commit.
  • Output: your policy matrix as a JSON world in ~/lab10/, the resolver output for every target, the probe output from one of your own sessions, a guardrail action table for the three messages, and a one-page change request for the admin. Keep all of it out of commits.

What “clean” looks like

On main with git status --short empty, no local lab10/* branches and no ~/lab10 working folder. If you are an admin, no profile named harbourline-* exists at any scope you control and no profile is bound to your test automation or session; otherwise note which profile already governs your sessions (run probe.sh once and keep its output).

5.Acceptance criteria

You are done when someone who was not in the room can see each of the following.

  1. The matrix exists. ~/lab10/matrix.json has at least one enterprise profile, one organization default and one automation-level profile, and profile-resolve.mjs --validate reports no problems for it.
  2. Two destinations, nothing else. For a normal session the resolver shows registry.npmjs.org and a PayGate sandbox host allowed, and api.paygate.example, api.github.com, pypi.org and example.com blocked. The MCP list in force is empty.
  3. Opt-out goes nowhere. A session bound to "no profile" resolves to the same network list as your enterprise profile, and your note says which setting makes that true.
  4. Same opt-out, other setting. With injectors/recommended-floor.json you show the opted-out session and the child session reaching hosts the CISO forbade, and say in one sentence why.
  5. The automation is stricter. The webhook-triage target resolves to read-only git, read-only Devin MCP and a network list no wider than the normal session's.
  6. Helpers stay inside. The child target resolves to exactly the parent's profiles, even though the child asked for none.
  7. Timing written down. For floor-tightened, your note gives three answers: the running session now, the same session after it wakes, a new session. The resolver's --then output agrees.
  8. Builds checked. You resolved the snapshot-build target, found what the Python install needs, and wrote who must change which profile (or blueprint) so the build passes without widening normal sessions more than the CISO accepts.
  9. Drafts fixed. The GitHub-token draft and the hurried wildcard draft each have every problem named, with one unintended hostname per wildcard.
  10. Observer evidence. probe.sh output from one of your own sessions is saved, with a sentence on what it tells you about the profile governing you — whether or not you are an admin.
  11. Guardrails table. For each of the three messages and each AI Guardrails action, your table says what the sender sees, whether Devin acts on it, and where the event shows up later.
  12. Articulation drill completed with the voice coach (section 8), or against a timer offline. The gap report (or self-score) is saved in ~/lab10/ and not committed.

8.Articulation drill (voice coach)

The coach plays Harbourline's CISO. She is fluent in risk and audit, not in Devin settings, and she wants each sentence to be something she can repeat to her committee.

60-second framing

Lead with what is now true for every session, then the one word that makes it true, then what you still need from her. Stems you can use:

  • "From today every Devin session can reach…"
  • "What makes that stick is…"
  • "What I need from you is…"

Sinhala-first note: say the outcome first — two places, nothing else — before naming any setting or level.

Think-aloud checkpoint (T+10)

The coach asks what you are looking at and what you will check next. Answer with I see… I think… I'll try… I'll check…. At T+10 you should be deciding which list each destination goes into and at which level each profile sits, not polishing JSON.

Think-aloud checkpoint (T+45)

Same four verbs, later in the block. The CISO has just changed something. Name what a session that is already running does about it, and how you checked. If you need to read the resolver output, say "Give me ten seconds to read the resolver" rather than going silent.

Three-minute CISO update

Skeleton: What is enforced → Where it is set → Who can loosen it (nobody / whom) → What runs stricter → When changes land → What it does not cover → Ask. One fact per sentence. Name hosts, levels and profile names, not features. Pause after each heading word.

Objection round

The CISO raises one technical and one commercial objection, in character, about 90 seconds each. Reply with: acknowledge → boundary → evidence → offer. The commercial objection needs a number — of hosts, packages or builds. The objections themselves are not printed here.
